# 🚨 生产环境密钥安全警告

## 关键提醒

### ⛔ 上线后禁止修改

生产环境的 `AES_SECRET` 和 `MD5_SALT` **一旦上线投入使用，终身不可修改**。

### 为什么不能修改？

```
前端加密数据流程：
用户数据 + AES_SECRET → 密文 → 存储到后端数据库

数据读取流程：
后端密文 → 前端 + AES_SECRET → 解密 → 明文数据

如果修改密钥：
后端密文 → 前端 + 新密钥 → 解密失败 → 数据永久丢失 ❌
```

后端数据库只存储密文，不知道也不使用这些密钥，所以**无法帮你恢复数据**。

## 首次部署前必须完成

### ✅ 部署检查清单

**第1步：生成强密钥**
```bash
# 生成32位随机AES密钥
node -e "console.log(require('crypto').randomBytes(16).toString('hex'))"

# 生成随机MD5盐值
node -e "console.log(require('crypto').randomBytes(12).toString('base64'))"
```

**第2步：配置密钥**
```javascript
// config/prod.env.js
module.exports = {
  NODE_ENV: '"production"',
  API_BASE_URL: '"netops.vdian.net/api"',
  AES_SECRET: '"[生成的AES密钥]"',      // ⚠️ 务必修改
  MD5_SALT: '"[生成的MD5盐值]"'        // ⚠️ 务必修改
}
```

**第3步：多地备份**
将密钥备份到至少3个安全位置：
- [ ] 团队密钥管理系统（如 1Password、Vault）
- [ ] 加密的私有Git仓库
- [ ] 团队共享的安全文档
- [ ] 离线加密存储（如加密U盘）

**第4步：测试验证**
```bash
# 测试环境验证
npm run build
# 部署到测试环境
# 测试加密/解密功能
# 确认数据能正常保存和读取
```

## 如果密钥丢失

### 后果

❌ 所有用户的历史加密数据永久无法解密  
❌ 用户需要重新设置所有加密内容  
❌ 可能影响用户体验和数据完整性  
❌ 无任何技术手段可以恢复  

### 应急措施

1. 立即从备份中恢复密钥
2. 如果所有备份都丢失：
   - 生成新密钥
   - 通知所有用户数据已失效
   - 用户需要重新设置
   - 清空后端数据库中的历史密文（可选）

## 如果必须更换密钥

### 场景

只有以下情况才考虑更换：
- 密钥泄露给外部人员
- 安全审计要求强制更换
- 准备放弃所有历史数据

### 步骤

1. **评估影响**
   - 统计受影响的用户数量
   - 评估数据丢失的影响范围

2. **用户通知**
   - 提前通知用户数据将失效
   - 引导用户导出重要数据
   - 设置足够的迁移时间窗口

3. **数据迁移（可选）**
   ```javascript
   // 如果需要迁移，必须在更换密钥前
   // 1. 用旧密钥解密所有数据
   // 2. 用新密钥重新加密
   // 3. 更新后端数据库
   // 注意：这需要后端配合，且非常耗时
   ```

4. **更换密钥**
   - 修改 `config/prod.env.js`
   - 重新构建并部署
   - 清空用户浏览器缓存

5. **后续处理**
   - 用户重新设置数据
   - 监控错误日志
   - 处理用户反馈
